# La version web n'a pas d'hébergement qui permette les threads

## Constat

Le prototype de #347 vit sur lumiel, dans `out/347/` du worktree lancement.

Les threads wasm demandent une page isolée : `Cross-Origin-Opener-Policy: same-origin` et `Cross-Origin-Embedder-Policy: require-corp`. Sans eux, le build à threads échoue tout de suite (`SharedArrayBuffer transfer requires self.crossOriginIsolated`).

Sur le serveur local `out/347/web/server.mjs`, qui pose ces en-têtes ou non, l'extrait prend 7,2 s sur 12 threads, contre 13,7 s sur un fil.

Le `vercel.json` minimal est `out/347/vercel.json` : il pose les deux en-têtes sur `/(.*)`. La page embarque tout, et `require-corp` ne lui retire donc rien. Rien n'est déployé.

## À faire

- Une construction statique de la version web : page, scripts, wasm et Mediabunny.
- Le `vercel.json` dans le dépôt.
- Un premier déploiement sur Vercel, après accord de l'utilisateur.

## Critères

- Sur l'adresse déployée, `crossOriginIsolated` vaut `true`, et le build à threads se charge.
- L'extrait s'y calcule dans Chrome avec ses 403 détections et ses 4 pistes.
- Les en-têtes sont vérifiés par `curl -I` sur la page et sur le wasm.
